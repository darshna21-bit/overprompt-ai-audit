## AI Summary Prompt

Used in: `app/api/generate-summary/route.ts`
Model: `anthropic/claude-3-haiku` via OpenRouter

```
You are a direct, no-nonsense AI infrastructure advisor writing a 90-word audit summary.

Your team {companyContext} is running {tool} {plan} for {seats} seat(s) at ${monthlySpend}/mo, primarily for {useCase} work.

Top finding: {recommendation}
Potential saving: ${monthlySavings}/mo (${annualSavings}/yr)

Write in second person ("Your team..."). Lead with the single most impactful finding. Be specific — cite the dollar amounts. End with one concrete next action.

Rules:
- No filler phrases like "it's worth noting" or "in conclusion"
- No markdown or bullet points
- Plain prose only
- Exactly 80–100 words
```

---

## Why I Wrote It This Way

**Second person ("Your team..."):** Creates a personalized tone without needing the user's name. "Your team is overpaying" lands harder than "The team is overpaying."

**Lead with the finding:** The summary sits above the detailed breakdown on the results page. If it opens with context ("Running a 5-seat team on Cursor Business...") instead of the finding, users skip it. Opening with the finding earns attention.

**Cite dollar amounts:** The numbers are already in the prompt. Forcing the model to include them prevents vague outputs like "significant savings potential."

**One concrete next action:** Ends the summary with forward momentum. Without this constraint, Haiku tends to end with observations rather than calls to action.

**80–100 word limit:** Short enough to read in 10 seconds on the results page. Tight enough that the model can't pad.

---

## What I Tried That Didn't Work

**First attempt — no word limit:** The model wrote 200–250 word summaries with a lot of "it's important to note" filler. Adding the strict word range fixed this almost entirely.

**Second attempt — "write a professional analysis":** The tone came out like a consulting report. Cold, formal, and forgettable. Changing to "direct, no-nonsense advisor" immediately improved warmth and action orientation.

**Third attempt — asking for bullet points:** Bullet points broke the flow on the results page (which is already broken up by the per-tool cards). Switching to "plain prose only" made the summary feel like a human wrote it, not a formatter.

**Model choice:** Initially tried `openrouter/auto`, but its non-deterministic routing caused inconsistent tone, length, and quality across runs since it dynamically selects different models. Switched to explicitly pinning `anthropic/claude-3-haiku` for predictable, production-ready behavior. Also evaluated `anthropic/claude-3-5-sonnet`, which produced slightly higher-quality summaries, but latency was significantly higher (2–3s vs ~700ms for Haiku) for a short 90-word summary. Given the minimal quality difference at this length, Haiku’s speed advantage made it the better choice. For longer summaries or reasoning-heavy tasks, Sonnet would be more suitable.

## Fallback Behavior

If the OpenRouter API fails (timeout, 429, 500), or if the model returns an empty string, the route returns a templated fallback string generated by `generateFallback()`. The fallback is meaningful — it uses the input data to produce a real sentence — not a generic error message. Users see a useful summary regardless of API availability.
